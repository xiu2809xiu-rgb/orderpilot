# ADR 0059: The AI gateway and the person in the loop

- **Status:** Proposed. The gateway is area 1's and its destination check is area 4's, so Richie accepts or declines it in review.
- **Date:** 2026-11-21
- **Story:** [#32](https://github.com/xiu2809xiu-rgb/orderpilot/issues/32) (P-17)

## Context

OrderPilot's tagline is "AI reads, rules decide, people approve" (CLAUDE.md, section 1). Three things in the brief meet in one place when a model is called. The AI may read, classify, extract, explain and draft, and it may never approve, buy, post, release goods or pay. Only synthetic data may go to a third-party AI without Spectra's written OK ([ADR 0024](0024-governance-base.md), point 6). And the module needs the AI cost of each document (capability G).

Several features will call a model: extraction and classification (P-18, P-21), mismatch explanations, drafts, and Spark (P-95). If each one reached a provider its own way, each would need its own destination check, its own handling of a hostile document, its own cost record and its own key. The rules would be five copies, and the safe one would be the one somebody forgot.

## Decision

1. **One gateway.** `LlmGateway` (`apps/api/src/modules/ai/llm-gateway.ts`) is the only way a feature reaches a model. For every call, in order: refuse inside a database transaction; ask the destination policy; fence the documents as data; run a bounded tool loop; check the answer; write one usage record; return. A feature gets text, a stream, or an object that zod has parsed. It gets nothing it could use to act.
2. **Three providers behind one port.** The port, `LlmProvider`, is one model request in plain data: no zod type and no SDK type crosses it. The mock is the default. The OpenAI-compatible provider takes a base URL, a key and a model, so Groq, Gemini's OpenAI-compatible endpoint, OpenRouter, NVIDIA NIM and a local Ollama work by configuration alone, and `gemini` and `groq` are presets that know their own addresses. The Bedrock provider is optional and loads its package on first use. `AI_PROVIDER` chooses one at start-up, and a provider whose settings are incomplete stops the API from starting instead of answering from the mock, so a screen that says Groq never shows scripted text.
3. **The mock is the default and works offline.** It plays a script registered for a feature, and a feature with no script fails loudly and invents nothing. Its token counts are a fixed function of the text, its cost is zero, and its source holds no network, SDK, environment, clock or random code (a test reads the source to prove it). Every result says `mock: true`, and `GET /ai/status` says it too, so the web app shows "Mock AI".
4. **The Vercel AI SDK sits under the providers, in one file.** `ai` 7.0.165, `@ai-sdk/openai-compatible` 3.0.87 and `@ai-sdk/amazon-bedrock` 5.0.135, pinned exactly. Only the adapters under `providers/` may import them (a test lists the imports of every file in the module). The translator makes one SDK call per request, with the SDK's own retries off, no tool given an `execute` so the SDK runs nothing, and one step only: the gateway's loop decides, and the gateway validates the model's JSON with zod so every provider answers to the same rule. Retries, the destination check and cost tracking stay in the gateway, where the SDK cannot change them.
5. **The destination check.** Before anything is sent, the gateway asks `AiDestinationPolicy`, a port whose one adapter calls area 4's `PolicyService.checkAiDestination`. Every call must say where its data came from (`origin`) and how it is classified, with no default, so a caller that forgets does not compile. The default rule is synthetic data only, for every provider. A refusal never reaches the provider, is audited with the rule, writes a `refused` usage record, and tells the caller only that it was refused, because naming the rule would tell a prober what a provider would take. A policy that cannot answer counts as a refusal. The same rule applies to the mock.
6. **Documents are data.** Everything untrusted (a document's text, a tool's result) goes inside a block fenced by a nonce drawn fresh for each call, and the instructions say only text outside a block can instruct the model. The guard strips the nonce and anything that looks like the fence from what it wraps, and drops control and invisible characters. This lowers the chance that a model obeys a document. It is not the control.
7. **The control is that nothing a model says can act.** The gateway returns text, validated fields, or a request for a read-only tool. A tool is built by a feature for one call, from its own read services, and the model can only name one in the list it was given. A tool's arguments are parsed by zod. It runs as the person asking, after the same permission policy the HTTP guards use says that person may, and a call with no person behind it may not have tools. A refused tool is audited. The loop is capped (`AI_MAX_TOOL_STEPS`, 5 by default). The module imports no service that changes an order, approves, pays, posts or sends (the audit writer and its own usage table are its only writes), and a test fails if one is added without a person deciding it is read-only. An answer is untrusted text until zod has parsed it, keys the schema does not name are dropped, and an invalid answer is asked for again with a note that never repeats the answer.
8. **Usage and cost per call.** `AiUsageTracker` writes one `AiUsageRecord` per call on every path: the end, an error, a refusal, or a consumer that stops reading a stream. It holds the feature, provider setting, model, tokens summed over every provider request, an estimated cost, latency, status, person, trace id, document, the data's origin and classification, attempts and a short reason code. It holds no prompt, document or answer. Cost is tokens times prices set in configuration, with no price table in code, and the default is 0 so a free tier shows `$0.0000`. A failed write is logged by class only and never fails the call.
9. **Keys live only in the root `.env`.** `GEMINI_API_KEY` and `GROQ_API_KEY` (or `AI_API_KEY` and the Bedrock settings) are read by `AppConfig`, and no response, audit row, log line or error carries a key or a base URL. `GET /ai/status` shows the provider, kind, model and the mock flag, never a key. `pnpm ai:key` writes the key without it being shown, and `POST /ai/probe` (System admin, one fixed synthetic prompt, audited) checks that it works.
10. **Images, tools and streams are in the one gateway.** A page image goes to the vision model (`AI_VISION_MODEL`, falling back to `AI_MODEL`), at most `AI_MAX_IMAGES_PER_REQUEST` (3) a request. Tool calling and streamed answers are scripted by the mock, so Spark needs no second gateway.

## Alternatives considered

- **Each feature calls its provider's SDK directly.** The destination check, the fence and the cost record would each be written many times, and the one a feature leaves out is the one that fails.
- **The SDK's own hosted gateway, or a string model id.** A bare id routes through that gateway. The translator takes model objects only.
- **The SDK runs the tools.** It would run them before our permission check and our audit. No tool is given an `execute`.
- **A price table in code.** Prices drift, and a stale one reads as a fact.
- **A prompt-injection filter as the main defence.** A filter can be got around. It is kept as a way to lower the odds, and the control is that no output can write.

## Consequences

- **Spark does not use the gateway yet.** P-95 ([#233](https://github.com/xiu2809xiu-rgb/orderpilot/issues/233)) adds Spark's script and route. Until then no feature sends a model anything but the probe.
- **A real provider has been called by no test and no run of this story.** Every test uses the mock or an injected fake server. The Bedrock provider has never reached AWS.
- **The destination rule is area 4's.** If they change it, the gateway follows, because it adds nothing to the answer and takes nothing away.
- **The destination check is only as true as the classification and origin the caller declares.** The gateway never reads the documents, so a feature that labels real data as synthetic would pass. Each feature's reviewer checks that its origin and classification are honest.
- **The three SDK packages are runtime dependencies of the API,** and a major version change touches the translator alone.
- **A free-tier provider may keep and use what it is sent.** That is why the default is synthetic data only, and why the example file says so.
