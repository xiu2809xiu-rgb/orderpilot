## How they were made

- Each picture is named `<what>-<role>-<width>-<light|dark>.png`.
- The submitted orders were made through the API as Support. The Versions tab, audit trail and Checks pictures show one order, which Support revised twice through the API (PO version 3). The panel pictures use orders of their own, typed in on the New order form and refused, so the order numbers differ from picture to picture.
- The picture of the stale panel was made by confirming a revision through the API while the panel was open, then pressing Confirm on the page.
- Each role's picture is that role's own demo sign-in opening the order.
- The build's line was "images (api web) built from 9f10964c".

## Not shown, and why

- A Checks result that holds a PO version, or none ("Ran on PO version N", "PO version not recorded"): no stored order has a check result on this data, because orders typed in on the form are not checked. The wording was seen on a seeded sample order whose order answer was changed in the browser to say PO version 2, which is a staged state and not a picture of the product.
- A role that may create an order but not read it: no such role exists, so the duplicate notice's "could not be read" sentence was seen with the read answered 403 in the browser, and no picture was kept of it.
